# Fixed C01 final collector

`python -B -m experiments.time_cut_v2.recorded_real.final_collector --help`
describes the new explicit entrypoint. This is source preparation only. It does
not authorize a real run, publication, another case, an LP, or a changed model.

The controller requires all historical/replay/logical/capture paths and pins
used by `suffix_window`, a canonical reviewed source policy, the final registry
and its independently retained actual registration return, CPU 0, worker CPUs
1–5, a fresh attempt, and two distinct external output paths:
`--runtime-return-output` and `--collector-output`. Only registry mode exists.
Before launch it requires the exact 2,718 canonical blocks, 695,712 unique
models, 12,172 indexed nonempty-action queries, 9,666 separately retained empty
queries, and 7,652,832 original model occurrences for C01 H4/eight Sites/2,047
Regions/D1/no external incumbent.

The fixed `FINAL_COLLECTOR` guard includes all preflight and publication in its
3,600-second entry deadline. It grants 16 GiB coordinator AS, sampled 20 GiB
group RSS, 16 GiB host-available and 20 GiB disk floors, and 1 GiB total charged
evidence with 16 MiB reserved for the supervisor. The controller has 512 MiB AS.
Four 1 GiB family workers use CPUs 2–5 and the reviewed `interval-join-v1` gate;
they are reaped before collection continues on coordinator CPU 1. No numerical
solver subprocess is launched. The producer/optimizer import fence precedes
all mathematical imports, and loaded modules and current interpreter are bound
to this reviewed checkout and the explicit `final_collector` entrypoint.

Fresh genuine family verification and population admission precede exactly one
cold reconciliation of every successful numerical receipt and dependency. The
existing planner joins all original queries, and its empty bridge consumes the
untouched authenticated v2 trace. The existing witness helper makes one further
pass through selected source archives, freshly checks selected certificates and
physical witnesses, and exhausts their pinned bytes before its callback stream
can seal. The runner keeps at most 8,192 compact ordinal/receipt pointers. The
physical request array's canonical hash and byte count, each distinct query
binding, and the planner's original query-row digest are checked again.

Selected recovery entries use the same cold-admitted registry authority as
ordinary entries. The selected-reader adapter binds the exact admitted recovery
plan and consumes each chronological ancestor once, respecting finalized and
interrupted-prefix policies. Root and intermediate retained references resolve
directly to full model certificates; exact-only current recovery still freshly
checks every selected physical witness. A complete historical proof footer
does not upgrade a failed runtime. Existing source pins, actual current runtime
return and actual registry registration return remain required. The fixed
event population stays disjoint: 12,172 nonempty plus 9,666 empty equals 21,838.

Eleven named files are emitted: binding, family ledger and summary, reconciled
registry, query plan, physical request rows, physical receipts and summary,
empty partition, mixed query results, and collector summary. JSONL is streamed
through the synchronous charged writer; every write is at most 64 KiB. Large
original input archives remain external dependencies, with their complete
original pins and receipt/source chain retained in the reconciled registry.
No additional spool, producer thread, or full witness list is used.

Final continuity uses safe regular-file opening with no symlink path components
and device/inode/mode/size/mtime/ctime identities captured before admission.
The complete historical replay and logical attempt trees and every registered
receipt attempt tree are inventoried once, including directories, runtime
controls, journals, spools, and files not listed as evidence payloads. Closed-tree
identities also retain link counts. Late additions/removals change the retained
directory identities. Separately retained proof dependencies from failed history
keep their individual file identities; this does not assert that a failed
historical runtime was accepted.
Any observed replacement or write aborts final acceptance. This is metadata
continuity after byte-authenticated admission, not a third historical archive
hash pass or host attestation. Source bytes and policy are checked again through
worker manifest completion and controller publication. The controller separately
cold-checks its own bounded output against the actual successful guard return
and checks output identity through final publication.

Each mixed row follows the original global query event order. Nonempty-action
rows retain the unchanged query join, all primary/secondary/winning tie runs,
bound audit, distinct query binding and selected physical receipt pointer.
Empty-action rows retain the exact recovered original row and audit. Zero legal
languages remain distinct from nonzero languages whose models are all excluded.
Exact negative infimum gaps and missing required bounds are completed findings.
The selected physical point's actual `J` is stored separately; a fixed-epsilon
approach point is never called a point-level counterexample. Evidence completion
and the single-C01 case-bound status/acceptance are separate. A violated or
missing bound leaves case acceptance false. Whole-M5, full-C32, full-population
and literal-G8 global completion flags remain false in every result.

Only the actual `run_phase` return is retained, without reconstruction. If a
later check or write fails, completed raw evidence and that actual returned
object remain available, but no collector acceptance is issued. The acceptance
sidecar is exclusive and revoked on late publication failure. The CLI succeeds
for completed collected evidence even when its mathematical finding is a bound
counterexample; consumers must inspect the separate case-bound fields.

Tests use tiny genuinely checked families, explicitly protocol-fake receipt
factories, mocked guard calls, and bounded temporary files. They establish
assembly and failure handling, not a successful real C01 invocation. Final
launch still requires the complete registry/retained-byte inventory and an
independent integration review.
