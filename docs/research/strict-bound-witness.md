# Development-only strict-bound witness extraction

No real API integration or new full-size solve. The helper consumes an existing live SAT model. Every free constant must have an exact typed value without model completion. An exclusive, atomically published candidate file remains explicitly UNVERIFIED_CANDIDATE even after verification; partial/existing output is never accepted as a certificate. No candidate-file import API is provided.

The bound must equal the encoding's original upper bound. Both continuous copies share discrete action, segment and maximum selectors and satisfy the same fixed affine fiber. The original roots plus J(x)<b are independently evaluated. Since J(y)<=b and y has strict positive charges, the exact midpoint preserves all affine constraints, has strict positive charges and J<b. Every continuous coordinate, including wait and inactive suffixes, is interpolated; discrete coordinates remain unchanged. All roots plus x's strict constraints are then independently evaluated again. Original grounding and Fraction replay must match J,Q,H and plan exactly and confirm J<b. Neither a SAT result nor a candidate file certifies an attained improvement by itself. No optimality conclusion is returned.

Caller must charge extraction, independent evaluation and replay to the same original deadline and external resource envelope. Deadline/failure exceptions prevent a verified return; a candidate may remain as unverified evidence. No generalized bound interpolation, bisection, full-key optimization or later-stage skipping is implemented.

## Opt-in complete-depth integration

`decide_real(..., extract_witness=True)` requires the bound to equal the freshly replayed incumbent's value. The original absolute deadline and resource guards cover the one SAT query, extraction, two exact evaluations, replay and exclusive result publication. Tiny-profile defaults and non-extracting real calls remain unchanged. No new solver calls are added.

After successful replay, witness.verified.json stores the result and payload hash separately from candidate.unverified.json. It explicitly requires a successful consumer terminal receipt: a hard interruption may leave a mathematically replay-verified file without an in-budget complete outcome. Ordinary post-link deadline failure removes the newly published verified file. Caller final source/input/audit verification remains mandatory within the same deadline.
