# Milestone 5-D: deployable search design and preregistered protocol

Status: design and data gate, 2026-10-11. Branch `dot/m5d-deployable`, based on `1af12a96ca7de909f5971e49f118322117bf07ec`. This document authorizes no formal comparison, final holdout, or change to the accepted v2 semantics. The D0 source fingerprint is in `results/milestone_5d/d0_20261011/source_manifest.json`.

## D1: exact model and status contract

The candidate domain must bind the road graph hash, selected-leg router and numerical contract, direction and tie policy, Site catalog version, original Region tree, OD/SOC/activity/schedule parameters, charging and service representation, mobility budget, depth policy, and candidate restriction. Site ID is the action identity; road anchor is physical location. Co-attached Sites remain distinct, and a destination anchor is terminal. Each selected fastest leg contributes its frozen binary64 time and **its own actual length**, interpreted as exact rational constants. The latter is not a shortest-distance metric.

Preserve the lexicographic key `(J,Q,H,Π)` with `J = elapsed clock + λH`; report Q, H, and Π only on the attained face of all preceding coordinates. Strictly positive charging remains continuous. A sequence may have an unattained J infimum; then Q and later coordinates are undefined. If J is attained but Q is not, report no executable full-key optimum. A feasible incumbent is not an infeasibility proof. Explicit result statuses are `attained_optimum`, `infimum_unattained_J`, `infimum_unattained_Q`, `infeasible_within_declared_domain`, `incumbent_search_failed`, `time_limit`, `memory_limit`, and `verification_failed`, with separately recorded incumbent, proved bound, gap, and executable witness.

## D2: bounded exact search

Construct a deterministic feasible seed independently of REF and of either FLAT/HIER output. Verify its physical witness and charge/schedule constraints in the same domain before using its finite primary value `U_J`. Give FLAT and HIER the identical seed and charge its construction cost to both. If minimum mandatory stop overhead `h_min > 0`, `λ ≥ 0`, and `η = h_min + λ > 0`, the accepted v2 depth result permits `H_max = floor(U_J/η)`; retain equality depths. An H4 cutoff is diagnostic unless this proof independently yields H4. Never infer unrestricted infeasibility from a failed seed search.

Persist OPEN state, domain/source hashes, incumbent witness, certified lower bound, and checkpoint version. Resume only after exact bindings match. Prune by primary lower bound only when `L_J > U_J`; equality remains live for Q/H/Π. A Region lower bound over a parent superset may bound a child subset; a child proof cannot certify its parent, and a superset bound is not exact inherited-mask emptiness. Report queue, route, seed, proof, and verifier work separately.

## D3: route and Region interfaces

Freeze a directed route-cache key containing graph hash, source/target anchor, direction policy, selected-route tie policy, floating-point accumulation contract, backend/compiler version, and landmark version. A cache hit returns the same selected route time and actual length; it never reroutes a chosen leg as a different edge. Setup scans, landmark construction, cache misses, and memory count in cost. Validate pair against accepted full-label output on a prespecified real subset before exporting. Preserve signed-zero provenance on identity legs.

Directed ALT may use `max(0, d(L,t)-d(L,v), d(v,L)-d(t,L))` only for finite terms individually; skip every subtraction with a nonfinite operand. Taking a maximum after dropping infinities must not silently assert an unproved term. A Region summary may use certified minima/maxima over its complete member set to lower-bound all members, with graph/direction/landmark/member hashes bound. Internal Region queries cannot scan individual Sites; member scans form the explicit ablation. An independent offline checker recomputes representative inequalities and checks admissibility and hierarchy coverage.

## D4: retained data gate

The existing server selection manifest has 8 ODs × 2 activity modes × 2 SOC states = 32 query states, 16 OD/mode pools, 8 selected Sites per pool and 95 unique selected Sites. Full ordered pools have 2,749 energy-only Sites and 47,878 energy-and-scheduled Sites per OD. The preparation export covers 16 tables, 1,231 requested pairs, 105 identity pairs, and zero unreachable pairs; it reports no optimization. These figures establish available data, not that the desired 12 OD × 2 SOC × 2 activity = 48-query main design or 32/128 nested candidate sets have been frozen. The existing 8-Site selection is insufficient for those sizes. Source manifests, exact hashes, and selection rules must be checked before extending pools.

For each proposed OD/SOC, calculate a conservative lower bound on required charges using **road shortest distance lower bounds** and a proved maximum distance per full charge, with starting SOC handled explicitly. The selected fastest-route actual length is not a valid lower bound because it is nonmetric. Mark unknown when graph-distance certification is absent. Count independent ODs with `Q_req ≥ 2` by activity and SOC; the target is at least 12 main queries. If the data cannot supply these without contrived battery parameters, preregister the smallest geographic or OD extension and its source hashes before running performance comparisons.

## Experimental protocol and limits

Pilot: six prespecified base queries at nested 8/16/32 candidate counts, with at most 120 s, 4 GiB, and one concurrent worker per run. Main: 12 ODs × two SOC × two activity states at 32/128 candidates, at least six prespecified full-candidate cases, with at most 600 s, 8 GiB, and two concurrent workers. Candidate sets are nested; OD/geographic holdout assignments and all query inputs are frozen before results. Compare exact FLAT and deployable HIER with the same independently verified seed, plus HIER member-scan ablation and any separately justified comparable literature method. Do not use the final holdout in this task.

The aggregate new numerical budget is 48 CPU hours and 16 GiB RAM with host margin. Reserve CPU hours before each phase; a 48×2×2×600 s upper-bound schedule costs 32 CPU hours at one charged CPU, so three full repeats would exceed the budget. Run one main comparison and repeats on a preregistered representative subset only. Record actual CPU time, thread count, peak RSS, process-group termination, seed/setup/route/search/verification costs and `budget_exhausted_unrun` for cases not started. Timeout and memory limit are censored outcomes, not infeasibility. No formal run starts until D4 input feasibility, route contract calibration, independent checker, and query manifest are frozen.

## Test authority

Accepted predecessor regressions test the current implementation; refuted B21 v0/v1 historical examples remain refutation evidence, not acceptance tests to rewrite. New M5-D tests should target exact-key unattainment and witness validity, same-domain seed/depth/equality, directed ALT infinity handling, Region superset direction and source binding, nonmetric charge-distance gate, cache tie/direction, co-attached Sites, and fail-closed checkpoints. No million-model certificate rerun is needed for this design phase.
