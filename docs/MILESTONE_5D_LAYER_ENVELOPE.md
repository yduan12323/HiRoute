# Opt-in completed-layer evidence envelope

`timecut5.layer_envelope.run_layer_envelope` connects the existing FLAT/HIER
checkpoint and incumbent hooks without changing either solver core. This is a
completed-layer reconstruction adapter, not full D2 checkpoint acceptance.

## Evidence and reconstruction

The adapter starts from a freshly independently replayed original seed. It
persists an exact ordered frontier/terminal description, counters, effective
incumbent state, source/domain/policy bindings, replay-history hashes and an
embedded verified feasible witness in one atomic layer record. On recovery it
repeats the original search from the original seed and compares every recorded
layer hash and the saved boundary before continuing. Callable witness lifts
are regenerated by the same source and inputs; observable descriptors are not
deserialized as executable frontier state. Original H_ref and reconstruction
pruning inputs are preserved. All replay, persistence and verification costs
belong to the invocation's resource accounting.

The saved conservative primary bound is the minimum over current frontier
prefix bounds, retained terminal-piece relaxed affine primary infima and the
verified feasible upper bound. Empty components remain null. The feasible
upper-bound cap covers domains strictly pruned at previous thresholds. The
saved witness objective must not exceed the original seed or effective engine
scalar. This is primary-coordinate evidence only: no global lexicographic gap,
optimality or attainment claim is exposed.

## Caller and persistence responsibilities

Trusted binding suppliers must recompute actual query, candidate, route,
numeric, transitive-source and bound-policy/configuration identities. They
must not copy identities from the saved record. Fresh independent physical
verifiers must use the same admitted domain. The module does not discover or
authenticate those inputs automatically.

Candidate improvements are separately persisted in an `.incumbent` artifact;
each layer embeds its own verified copy, independent of later file changes.
File fsync, atomic rename and directory fsync are used. Errors propagate and
invalidate the current instance. A post-rename failure may leave a new visible
generation, requiring independent replay to resolve the outcome. Existing
destinations are refused; use a new destination for recovery.

Only a committed complete-layer boundary survives. Mid-layer work is recomputed.
An empty next layer does not trigger a layer hook, and no final completion
envelope is fabricated. Saved records remain `incomplete_boundary_evidence`,
even if primary lower and upper coordinates coincide. Only the returned exact
solver terminal status establishes completion.

## Validation and remaining work

Sixteen new synthetic tests cover both engines, original-core outcome/action
parity, REF comparisons including unattained infima, heterogeneous frontiers,
equal-primary secondary improvements, tampering and binding changes, truncated
replay, and interruptions around atomic replacement. They run through the
existing recovery-test CI discovery in normal and optimized Python modes.

This portable increment does not include production table-free launcher
bindings or large-graph interruption experiments. Those require separate
integration, independent verification and bounded end-to-end tests. It does
not support arbitrary mid-layer restoration or close full M5-D acceptance.
